## Architecture findings

- The morph assets are physically present in the RBXL under `ServerStorage/Models/Services` (models `M`, `FB`, `F`, and `MY`). They can be extracted and reconstructed locally; the client-side implementation must move the required assets into a local container and replace the original server morph call.
- The original morph UI calls `ReplicatedStorage.Events.Morph:FireServer(...)`. The actual `LoadMorph` function is in a server script: it clones the morph model, removes classic clothing/CharacterMeshes, hides the matching R6 limbs, creates Motor6D connections, and invokes `JiggleAssetService.ApplyMorph`. This exact event path will not work in a strictly local recreation, so the local morph path must be rewritten.
- The file has 96 `Animation` instances (95 with URI content) and 33 `KeyframeSequence` instances. It also contains a `ReplicatedStorage/CFrames` folder with animation data modules. A local animation system is plausible, but must be tested against the target executor and rig type.
- Geometry and media are mostly references to Roblox assets rather than embedded binary geometry: this file contains URI references for MeshParts, UnionOperations, SpecialMeshes, Decals, Textures, sounds, and UI images. Those assets still need to be accessible at runtime.
- A vanilla client script cannot use Roblox `loadstring`; the requested `loadstring(game:HttpGet(...))()` entry point depends on the executor providing those functions. Roblox documents `loadstring` as server-only in normal experiences.
- A single entry URL can be the bootstrap, but for this place a practical payload should be chunked into separate data/code files. Reconstructing 311k instances in one tight loop is likely to stall or exceed executor memory/HTTP limits. The loader should stage work and allow selective loading, especially for `ServerStorage/Maps`.
- Server-only gameplay, remotes, data persistence, server validation, and multiplayer replication are deliberately excluded. They cannot be turned into true shared functionality by a client-only reconstruction.

## Recommended conversion structure

1. A small `loader.lua` fetched by the one-line executor command.
2. Static data chunks containing instance definitions, parent relationships, properties, and asset URIs.
3. A client runtime layer that builds local models, recreates local UI, runs adapted LocalScripts/modules, and provides local-only morph/animation controls.
4. Optional streaming/region loading for map assets so the client does not instantiate all 311k objects at once.
